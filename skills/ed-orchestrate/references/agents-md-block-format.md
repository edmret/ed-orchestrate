# AGENTS.md generated roster block

`ed-orchestrate-init` renders a human-readable copy of `agents.json` into the target
project's `AGENTS.md`, so any harness that auto-loads `AGENTS.md` (opencode,
Antigravity/agy, and Claude Code via the `CLAUDE.md`/`AGENTS.md` convention) sees the
roster in plain prose, not just JSON. This is generated output — `agents.json`
remains the sole source of truth (see
[agents-json-schema.md](agents-json-schema.md)).

## Delimiters

Follows the same marker convention already used in this user's other real projects
(e.g. `<!-- BEGIN:nextjs-agent-rules -->` in `new-proy/AGENTS.md`) — own namespaced
id so it can't collide with other generated blocks:

```
<!-- BEGIN:ed-orchestrate-roster -->
...
<!-- END:ed-orchestrate-roster -->
```

## Exact rendered shape

```markdown
<!-- BEGIN:ed-orchestrate-roster -->
<!-- Generated by ed-orchestrate-init from .orchestrate/agents.json — do not
     hand-edit between these markers; re-run ed-orchestrate-init instead.
     Last generated: <ISO date>. -->

## Sub-agent roster (ed-orchestrate)

This project delegates coding sub-tasks to configured sub-agents via the
`ed-orchestrate` skill (Claude Code) — the same roster is honored by opencode and
Antigravity/agy through this file. Full machine-readable config:
`.orchestrate/agents.json`.

| Role | Harness | Model | Provider | Effort | Default mode | Fallbacks |
|---|---|---|---|---|---|---|
| coder | opencode | qwen3.6 | nan | — | handoff | claude (sonnet), codex (gpt-5.5) |
| planner | claude | opus | — | high | supervised | — |

Default role when unspecified: **coder**.

To delegate: ask for "hand off <task> to <role>" (fire-and-forget) or "supervise
<role> on <task>" (blocking/monitored). To change this roster, run
`ed-orchestrate-init` again.
<!-- END:ed-orchestrate-roster -->
```

`Provider`/`Effort` columns render `—` when the field is `null`. `Fallbacks` lists
`<harness> (<model>)` pairs comma-separated, or `—` when the role has none. A
same-harness fallback (no `harness` key in the entry) renders using the role's
own primary harness, since the two are the same binding target; each fallback's
provider and effort are deliberately omitted to keep one row per role —
`agents.json` holds the full binding.

## Idempotent splice algorithm

Implemented in `ed-orchestrate-init/scripts/render_agents_md_block.py`:

1. Read the target `AGENTS.md` if it exists; treat as empty string if not.
2. Search for `<!-- BEGIN:ed-orchestrate-roster -->` … `<!-- END:ed-orchestrate-roster -->`
   with a `DOTALL` regex.
3. If found — replace that exact span in place with the newly rendered block. Every
   byte outside the span, regardless of where the span sits in the file, is left
   untouched.
4. If not found — append the new block at end-of-file, preceded by a single blank
   line if the file is non-empty; if the file is empty or missing, the block becomes
   the entire file content.

This guarantees re-running `ed-orchestrate-init` after the user has hand-edited
unrelated parts of `AGENTS.md` never disturbs that content — see the idempotency
regression test in the skill's verification plan.
